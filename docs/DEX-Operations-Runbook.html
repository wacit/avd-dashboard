1 · Daily 5-minute check

  1. Open /os. Read the DEX pill in the taskbar tray: 80+ fine · 60–79 look · <60 act.
  2. Score Trend — any dip overnight? Note the time bucket; you will correlate it in Errors / Host Performance.
  3. User Experience — the top of the list is the worst experience in the environment. Anyone under 60? Click their name (Section 3).
  4. Agent Telemetry — feed line should say all hosts reporting. Fewer hosts than expected → Section 11. Check Unhealthy services (should be empty) and Disconnected / long-idle sessions.
  5. Classic view alert strip (/) — any WARN/BAD KPIs → Section 8.

2 · Reading the experience score

Every user, host, and the environment gets a 0–100 score: a weighted average of factor sub-scores. Each factor maps its raw metric linearly from its good band (100) to its bad band (0). Missing data drops the factor and reweights the rest — so a score built only from Log Analytics is valid, and gets richer once agents report.

3 · Playbook: "my session is slow"

Path: User Experience → click the user → User Detail window

  1. Find the user (they are probably near the top). Note which columns are out of band — the score chip tells you that it's bad; the columns tell you why.
  2. RTT high (>150 ms)? Network path. In User Detail, check the latency trend: constant = distance/ISP; spiky = Wi-Fi or congestion. Cross-check UDP % and Loss % for their host in Agent Telemetry — TCP-only means Shortpath is blocked and adds latency.
  3. Input delay high but RTT fine? The host, not the network. Open the session's host (click it inside User Detail) — look at CPU queue, CPU %, and Top CPU app. A saturated host or one greedy app (CAD, browser tabs, AV scan) is the usual cause.
  4. Crashes listed? The app is the problem, not the platform — note the faulting application and version.
  5. Logon slow too? Follow Section 4 for that user's profile/GPO rows.

4 · Playbook: slow logons

Path: Logon Waterfall + FSLogix Profiles + Agent Telemetry (GPO)

  1. Logon Waterfall — read top-down: the milestone where average seconds jumps is the phase to blame. Big Avg→P95 gap = inconsistent, usually storage or a subset of users.
  2. Profile the profile — FSLogix Profiles window: loads over ~30 s are storage. Check SMB ms per host in Agent Telemetry (good ≤ 20 ms). High SMB latency on all hosts = share/tier issue; on one host = that host's networking.
  3. GPO processing by user (Agent Telemetry) — anything over ~15 s is worth a GPO review (drive mappings, WMI filters, printers).
  4. Logon storms — if logons are slow only at shift start, check Host Performance CPU at that time bucket; consider staggering or pre-warming autoscale.
  5. Per-user: their User Detail window lists each session's Connect s and every profile/GPO load with timestamps.

5 · Playbook: disconnects / drops

Path: Short % column + Errors + Agent Telemetry network table

  1. Short % in the experience tables — sessions under 5 minutes. One user high = their network. Many users high = platform.
  2. Errors window — dominant symbolic code? Gateway/broker codes cluster when the platform is at fault.
  3. Loss % / Retrans/s / UDP % per host (Agent Telemetry, network table): loss above ~1% sustained or UDP 0% (Shortpath blocked) degrades and drops sessions.
  4. AVD agent health (Host Performance) — hosts flapping between Available/Unavailable drop their sessions; check the RDAgent services row in Agent Telemetry.
  5. Idle-logoff policies also produce short sessions by design — check the Disconnected / long-idle table before blaming the network.

6 · Playbook: one bad host

Path: Host Experience → click the host → Host Detail window

  1. The latest agent snapshot tiles answer most of it at a glance: CPU %, CPU queue (>2/core = waiting threads), free memory, SMB ms, free disk % (<15% → profile/temp bloat), loss %, UDP, stopped services, active vs disconnected counts.
  2. Stopped services — RDAgent/RDAgentBootLoader stopped = broker can't use the host; frxsvc stopped = profile failures for every logon.
  3. Current sessions — who is on it, their input delay, memory and top CPU app. One user at 8 GB with a runaway app explains everyone else's day.
  4. Disconnected sessions holding memory — log them off to reclaim capacity.
  5. Compare the agent resource trend with the Perf charts — if Perf is empty but agent data is present, the AMA perf DCR isn't collecting (onboarding runbook, Phase 0).

7 · Playbook: choppy / frozen screens

Path: Network & Graphics + Agent Telemetry (FPS, skipped frames)

  1. FPS below ~15 sustained = users see stutter. Check which resource starves it: frames skipped (server) = host CPU/GPU; (network) = bandwidth/loss; (client) = the endpoint device.
  2. Encoding time rising with CPU = the encoder is CPU-bound — for CAD/graphics pools verify hardware encode (AVC/HEVC policies) is active.
  3. End-to-end delay (graphics preview table) above ~200 ms feels like molasses even at good FPS — usually network RTT + encode time stacked.
  4. Bandwidth panel: sustained ceiling = the pipe is the limit (VPN hairpin, throttled egress).

9 · Weekly hygiene checklist

  • Score trend week-over-week (30d range) — trending down anywhere?
  • Top 5 worst users: recurring names? Open each detail once.
  • Top app consumers — is one app increasingly eating the pools?
  • App crash leaders — versions to update or plugins to remove.
  • Disconnected / long-idle sessions — log off, reclaim memory.
  • Free disk % per host — anything under 20%?
  • GPO processing creep — new policies adding seconds?
  • Agent feed: hosts_reporting equals host count?
  • Export CSVs (header dropdown) for anything you want to keep — the agent DB retains ~14 days.

12 · Future state: Grafana (self-hosted LXC)

The repo's grafana/ folder deploys Grafana OSS into a Proxmox LXC with everything provisioned: an Azure Monitor datasource for the AVD Insights tables, an Infinity datasource reading this dashboard's /api/dex score API, and an AVD DEX Overview dashboard (score stat + trend + factors, ranked users/hosts, connections / RTT / errors / logon / profile KQL panels, agent input-delay and host-saturation tables).

Use Grafana for what this app doesn't do: 30–90 day trending with annotations, alert rules that dispatch to Teams/email (suggested starter rules are in grafana/README.md), kiosk wallboards, and per-customer folders with RBAC. The Ops OS remains the interactive triage tool and the single source of truth for the score. Deploy:

  1. Copy grafana/ to the Proxmox host.
  2. ./setup-grafana-lxc.sh --ctid 240 --tenant-id … --client-id … --client-secret '…' --ip 192.168.1.240/24 --gw 192.168.1.1
  3. Set the dashboard's workspace (ARM resource ID) and dex_url variables; save. Bind the DEX app to 0.0.0.0 so the CT can reach it — trusted LAN only.

Phase 3 (when 90-day agent history matters): dual-write agent payloads to the Azure Monitor Logs Ingestion API (custom table AvdDex_CL) so agent signals become KQL-queryable next to the WVD* tables — documented in grafana/README.md.
